# 线缆删除与拆除

本轮范围：已保存的线缆。房间、机柜、设备、线槽删除，复杂光纤拓扑拆除，以及回收站恢复仍待实施。

## 用户操作

在线缆列表，或在 3D 中选中线缆后，打开“删除 / 拆除”。系统先读取当前线缆编号、状态、A/B 端点、路径段数量及阻碍；读取预览不会修改记录。

- **规划中线缆**：核对对象与影响后确认删除。
- **其他未拆除状态**：填写原因，再确认拆除并归档。
- **有依赖**：存在未完成工单、已登记光纤束／纤芯或铜缆线对拓扑时阻止操作。当前版本不自动级联移除拓扑，即使登记的束或线对尚未使用。
- **无权限**：显示权限原因，不能执行；默认所有者／管理员的 `*` 权限可用。既有查看者、编辑者和项目授权没有被自动扩大，需要相应的 `cable:delete` 或 `cable:remove` 权限。
- **发生冲突**：保留输入和选中对象，重新读取并核对预览后再提交。预览不预留对象，也不授予权限。

删除成功后从活动列表和 3D 场景移除，同一事务释放当前线缆的端接、端口占用及路径关联；端口可用于新的连接。原线缆、端接、路径、测试与审计历史保留，不重用原编号。拆除写入 `removed` 状态及原因；历史行保留不等于已提供独立归档查询页面。首版没有一键恢复。

未保存连线使用“取消连线”，临时测距使用“撤回／清空”；这些操作不等于删除数据库中的线缆。3D 中有安装、接线或编辑草稿时，先完成或退出草稿，再操作已保存线缆。

## 接口与事务

| 方法 | 路径 | 合约 |
| --- | --- | --- |
| GET | `/api/v1/cables/{id}/deletion-preview` | 要求 `cable:read`；返回对象版本、动作、端点、路径数量及阻碍 |
| DELETE | `/api/v1/cables/{id}?expected_version=N` | 仅 `planned`；要求 `cable:delete`，版本必须匹配 |
| POST | `/api/v1/cables/{id}/remove` | 非规划活动线缆；要求 `cable:remove`，JSON 包含 `expected_version` 与 1–1000 字符 `reason` |

执行时在项目及线缆锁内重新验证身份、完整对象范围、版本和依赖；服务端依次检查端点与已登记路径，不把当前 3D 已加载的部分对象当作全部关联。依赖阻碍不返回其他范围对象的名称或 ID。束／线对及线缆工单创建共享父对象锁，工作流继续使用线缆锁。数据库繁忙不自动重试写入。

释放端口占用时按 `owner_type=cable_termination` 和实际端接 ID 匹配。重复或过期请求不能释放后来接入的新线缆。对象软删除后旧请求返回不可用，不重复生成拆除记录。

## 数据库升级

迁移 `200000000011` 将 `cable_terminations` 的全历史端口唯一约束改为 `deleted_at IS NULL` 的活动唯一索引。保留线缆端别唯一性、检查约束和外键；PostgreSQL 直接修改约束／索引，不重建或关闭原表 RLS。

升级前备份。已有历史端接和新端接复用同一个端口后，旧数据库结构无法表达这份历史，因此 downgrade 会在修改结构前明确拒绝；不能通过删历史记录强行回退。需要回退应用时使用升级前备份，并评估备份后的业务变更。
