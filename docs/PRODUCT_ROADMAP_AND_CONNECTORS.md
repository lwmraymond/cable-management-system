# 产品化评估与设备对接路线

评估日期：2026-09-17。当前工作对象：本地 cable-management-system 的 3D 工作区，兼顾新空间规划和既有设施运维。

## 产品定位

将房间、机柜、设备、端口、线缆及线槽记录连成可操作的工作流程，作为物理基础设施记录系统。3D 用于定位、查看和安装规划；监控系统提供发现结果及运行状态，两类资料保留来源，经过匹配确认后关联。

本轮交付提升的是可用性与资料完整性检查，不能据此宣告生产版本已完成。既有后端权限、审计及冲突校验仍负责最终写入约束。

## 本轮产品改进

| 用户任务 | 已落实的交互 | 自动化边界 |
| --- | --- | --- |
| 第一次使用 | 左侧常驻使用指南、7 步教程、可搜索操作说明及快捷键、工具直接入口 | 不强制弹窗，不创建演示工程；阅读进度不冒充工程进度 |
| 新机房规划 | 工作助手按房间→机柜→设备→线槽→端口连接组织任务 | 缺房间或机柜时先引导完成前置工作，所有创建仍确认保存 |
| 日常查线 | 运维任务入口、对象检索、长度与端点核对、资料检查结果 | 不将未加载路由误报为断线，不将未知状态显示为正常 |
| 资料检查 | 每次场景数据更新后自动检查入口、尺寸、机柜边界、未入柜显示、路由、长度及策略 | 只分析当前已加载范围；缺失、截断与实际记录冲突分别提示 |
| 处理问题 | 问题清单带对象名称和对应查看／修改入口 | 仅已有入口可直接调整；不会自动放开策略、删除对象或重接已占用端口 |
| 减少填写 | 新房间／设备／线槽可填建议编号；设备可采用连续空闲 U 位 | 建议基于当前可见资料，不承诺全租户唯一；保存再次校验 |
| 操作稳定性 | 浏览助手／教程时保留接线草稿及测距、机柜视图聚焦、输入法及组合键保护、触屏平移、加载错误与空态分离 | 不增加全局键盘劫持，加载失败不显示无法使用的创建入口 |

教学正文见 [3D 用户手册](USER_GUIDE_3D.md)；工程行为及验证记录见 [3D 工作区](3D_WORKSPACE.md)。

## 自动化的下一阶段

| 优先级 | 改进 | 验收条件 |
| --- | --- | --- |
| P1 | 已有设备移柜／调整 U 位、已有线槽折点和既有线缆路线编辑 | 版本检查、占位冲突、端口引用保护、前后差异预览和原子保存；失败保留输入 |
| P1 | 批量安装方案 | 一次预览房间内的机柜网格、设备模板和路径清单；确认后整体提交；可解释每项冲突 |
| P1 | 草稿与操作恢复 | 长表单草稿按租户、用户、项目隔离；明确保存与草稿区别；离开时可恢复，不把旧草稿自动写回新上下文 |
| P1 | 标签密集场景优化 | 屏幕空间避让／按重要性精简；选中对象和长度优先，名称保持可搜索；用密集场景验收 |
| P2 | 线槽容量与选路约束 | 先补齐线缆外径、桥架截面、填充率与允许规则；数据不全时标未知，不生成虚假容量结论 |
| P2 | 工单与现场核验闭环 | 将资料问题转为有负责人、照片、测量值和复核记录的工单；完成后保留审计 |
| P2 | 周期检查和状态变化 | 后端任务记录上次成功时间、变化、失败和重试；只针对已配置空间运行，不依赖浏览器保持开启 |

## Observium 对接设计（尚未实现）

### 已核对的外部能力

Observium 官方文档将 REST API 标为订阅版功能；支持读取设备和端口，并支持只读 Bearer token。实际接入前应读取目标实例的 OpenAPI，核实版本、API 开启状态和账户权限，不假设所有部署能力相同。[Observium API 官方文档](https://docs.observium.org/api/)

### 本仓库可以复用的基础

- `apps/api/app/services/netbox_adapter.py` 已有 NetBox 客户端的受限资源、分页边界、429 重试，以及外部快照校验和与同步游标逻辑。
- `apps/api/app/integration_models.py` 已有 `ExternalObjectMap`、`NetBoxSyncCursor`、签名 Webhook 发件箱与投递记录。
- 当前 NetBox 同步依赖外部 `sim_local_type / sim_local_id` 自定义字段，主要维护绑定与元数据；它不是自动创建设备、机柜、端口和物理线缆的完整导入流程。
- 现有外部身份唯一键为租户＋adapter＋外部类型＋外部 ID。多实例接入前必须加入连接器实例维度，防止两个 Observium 实例中相同 device_id / port_id 冲突；迁移应兼容既有 NetBox 记录。

### 用户流程

1. **建立连接源**：选择 Observium、填写实例名称及地址、在后端设置凭据引用，绑定允许同步的租户／项目范围。
2. **测试连接**：检查认证、API 能力、可读取范围，展示权限不足、版本不支持与网络失败的具体原因。
3. **只读发现**：分批读取设备和端口，记录来源 ID、抓取时间、完整性、错误及校验和；先存发现快照。
4. **匹配本地记录**：优先已有绑定；序列号、设备名称和管理地址只用于生成候选，不因名称相同就静默合并。
5. **预览差异**：分别展示新增候选、属性变化、缺失来源、绑定冲突和将保持不变的现场字段。
6. **确认应用**：首次绑定和新增记录由用户确认；后续自动同步只更新已配置的来源字段，校验本地版本，保存审计。
7. **运维查看**：设备详情展示来源、上次成功同步、当前运行状态与数据是否过期；可跳转来源系统并查看同步历史。

### 字段归属与数据模型

| 资料 | 默认归属 | 同步规则 |
| --- | --- | --- |
| 外部 device_id / port_id、抓取时间、原始状态 | 连接器发现层 | 保留来源实例；字段标准化前保留可审计快照，不在日志中记录凭据 |
| 厂商、型号、序列号、系统描述、管理地址 | 来源候选资料 | 有绑定后按白名单更新；手工锁定字段保留并显示差异 |
| 端口名称、描述、速率、管理／运行状态 | 来源运行资料 | 与本地物理端口通过明确绑定关联；不因接口顺序变化重新编号本地端口 |
| 房间、机柜坐标、U 位、入口、线槽几何 | 本地现场记录 | 不从监控系统的位置文本推断三维坐标，不自动移动设备 |
| 物理 A/B 端接、跳线、路径段顺序、预留、实测长度 | 本地现场确认 | 逻辑邻接不能直接覆盖物理接线；只可提出待核实候选 |
| 来源设备暂时消失或同步失败 | 未知／过期状态 | 不自动删除本地设备及线缆；不把抓取失败标成设备离线 |

建议引入 `ConnectorInstance`、`DiscoverySnapshot`、`ReconciliationPlan`、`SyncRun` 四个有租户与实例边界的资源。外部绑定键包含 `tenant_id + connector_instance_id + external_type + external_id`，并在绑定时校验本地对象存在且位于授权范围。暂不实现双向写回。

### 对接验收

- 同一快照重跑不会重复建对象；两个来源实例同 ID 互不覆盖；跨租户匹配失败。
- 失效／过期凭据、429、超时、分页循环、部分响应、无权访问和来源字段缺失都有稳定结果。
- 后台请求使用配置的目标与后端凭据；重定向和分页不能将凭据带到其他来源，不从前端持有长期密钥。
- 失败不推进成功游标；重试有上限；并发任务和确认应用有幂等及版本检查。
- 发现记录与现场字段冲突时产生可复核差异，不静默覆盖。
- 用用户实际实例的脱敏样本验收设备／接口映射，再决定上线周期同步。

## 达到正式产品质量仍需的发布门槛

1. **真实环境身份与隔离**：在真实 OIDC 和 PostgreSQL Forced-RLS 环境完成角色与越权验证，关闭演示身份。
2. **编辑闭环与恢复**：完成上面 P1 的已存对象编辑、草稿恢复与差异核对，避免只能新增、难以维护。
3. **浏览器与使用场景**：覆盖常用桌面浏览器、触屏、键盘、窄窗口、空项目、首次失败、重试及长任务。
4. **容量证据**：建立代表性大小的机房数据，记录场景载入、帧率、内存、API 延迟及并发写入表现；未压测前不承诺生产容量。
5. **运维能力**：数据库与附件备份恢复演练、迁移回滚方案、可观察任务日志、故障告警、版本发布记录。

建议先把当前版本作为可操作的规划／运维试用版，在真实设施的少量已核实数据上完成端到端验收，再扩展连接器和批量任务。这里的路线顺序是产品实施建议，不代表这些后续功能已交付。
