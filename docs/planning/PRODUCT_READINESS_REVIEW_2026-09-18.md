# 产品质量复查与迭代顺序

日期：2026-09-18。范围：本地 `/app-next`、共用 API、工作流程、认证和部署。定位仍为兼顾机房规划与设施运维的试用版；本轮用源代码、隔离测试及本地浏览器核对，不以功能数量或测试总数推算完成百分比。

## 判断

已有房间、机柜、设备、端口、线槽、线缆、3D 安装规划、工作助手、教程、个人／共享空间和浏览器 SSO 接口，能演示较完整的业务链路。距离正式交付的主要差距是：资料不能丢、权限不能绕过、维护操作能闭环、安装升级可以重复、故障可以恢复。现阶段优先修正这些问题，再扩充连接器。

最终构建测量：首页入口与 HTML 预加载 JS 合计由 **1,856,659 B 降至 1,313,884 B（减少 29.23%）**；相同 Node gzip 算法为 **584,616 B → 418,504 B（减少 28.41%）**。计算包含入口及预加载共享模块，不仅统计 index 文件，也不代表真实网络耗时。现有大于 500 kB 的构建告警仍存在，3D 自身也仍是较大的动态模块。

### 本轮保护的边界

- 错误边界处理 React 渲染／懒加载异常，不会自动恢复丢失的编辑，不会重试提交，也不负责捕获每个按钮异步事件。
- 平面图对刷新／关闭页签提供浏览器离开提示；**应用内部切换页面、工作空间或工作范围的统一草稿保护仍未完成**。需要在父级导航和范围切换入口协调，而不能只在画布内提示。
- 入口限流使用服务端识别的客户端地址，同一 NAT 出口用户共享额度；真实代理必须按部署规则覆写转发头。认证后的独立账号额度尚未实现。
- 新增范围过滤优先保证不返回越权对象；大量对象时还需要将权限范围下推至分页查询，并核验查询次数和延迟。
- 范围修复覆盖 `GET /locations`、`/racks`、`/devices`、`/cables`、`/pathways`、`/work-orders`、`/test-results`、机柜 elevation、设备 ports，以及线缆安装／测试／审批和所关联工单。**通用资源创建、授权管理、搜索、报表、合规、审计与标签接口仍须逐组完成同等矩阵**。
- 本轮回归不能替代全 API 权限矩阵，也不能作为真实 PostgreSQL 强制 RLS 的运行证明。

## 审查中确认的剩余问题

1. **部署产物缺失**：`infra/api.Dockerfile:5–8` 只复制旧前端，未构建／复制 `apps/web-react/dist`。本地页面可用不代表容器具备新版页面。
2. **身份环境仍为开发配置**：`docker-compose.yml:19–25` 使用 Keycloak 开发启动和导入目录，缺少持久化配置；`infra/keycloak/sim-realm.json` 中回调需对齐新 BFF。不能只填一个 LDAP 地址就宣称登录接通。
3. **启动与恢复流程不完整**：Docker 启动及 `scripts/local-dev.py` 均执行迁移、演示 seed；当前没有数据库与附件配套恢复演练证据。
4. **发布检查覆盖不足**：尚无 `.github` CI 工作流；`scripts/check-web-react-source.sh` 的 `--noCheck` 是语法烟测，不能替代实际类型检查、Vitest 和生产构建。
5. **光纤操作目标不稳定**：`FiberEndpointPanel.tsx` 记录仅来自当前页创建，更换输入后仍可能释放旧记录；刷新后缺少加载已有端接入口。
6. **追踪结果陈旧**：`FiberTracePanel.tsx` 修改输入、查询失败后保留先前 trace，容易让用户误认新目标已有结果。
7. **业务详情与反馈仍有调试界面特征**：`RacksPage.tsx`、`CablesPage.tsx` 默认展示 JSON；线缆导出缺少页面级错误捕获和权限提示，`AsyncState.tsx` 没有统一重试入口。

8. **连接器实例隔离未完成**：`integration_models.py` 和 `netbox_adapter.py` 的外部绑定唯一键缺少来源实例，同租户两个来源的相同外部 ID 可能冲突。先补实例维度及迁移，再接 Observium。
9. **后台投递需要可靠性设计**：`signed_webhooks.py` 当前发送与提交之间缺少原子领取／租约，多 worker 或崩溃时可能重复发送；需有可恢复任务状态和接收端幂等，不能承诺恰好一次投递。
10. **健康与容量证据不足**：readiness 主要检查业务数据库 `SELECT 1`，未完整反映迁移、平台库及任务依赖；场景对象上限不是可承载量证明。

11. **3D 标签拥挤有实际画面证据**：本地约 694 px 宽窗口、Floor 2 场景出现标签重叠及边缘裁切。`rackGeometry.ts`／`roomGeometry.ts` 标签保持最小屏幕宽度，`sceneRenderer.ts` 维持屏幕尺寸但未做标签碰撞／越界抑制；场景适配又排除 Sprite，因而“适配全部对象”不能解决文字拥挤。相机已有按当前宽高比拟合和 ResizeObserver，本轮没有证据证明相机数学本身失效，不将截图中的视觉偏移直接判为几何越界。

上述文件均已实际阅读；需以实现后的回归测试关闭问题，不能仅把按钮改为中文或给页面换布局就标记完成。

## 产品验收场景

- 新用户：登录 → 个人或获授权的共享空间 → 新建机房与出入口 → 多机柜／设备 → 线槽 → 两端口连线 → 路线预览 → 确认保存 → 重新打开核对。
- 运维用户：按编号查线 → 在 3D 定位 → 核对端点、介质和长度 → 测试／复核 → 拆除或调整 → 验证端口释放与历史保留。
- 协作用户：viewer 只读、editor 按许可编辑、owner 管理成员；跨范围直接访问失败，授权撤销后不能继续读写。
- 故障恢复：断网、403、409、过期登录、分包失败、重复点击、浏览器刷新、版本升级之后仍能解释状态并继续工作。
- 部署人员：空环境安装 → 初始化管理员 → 接入身份源 → 备份 → 升级 → 新实例恢复 → 核对设备、线缆、附件和审计记录。

容量目标应由真实数据规模决定。建议使用小／中／大三组生成资料，分别记录冷启动、场景载入、相机帧率、内存、列表 API 的 P95 延迟和并发编辑冲突；本次未压测，不对可支持对象数作承诺。
