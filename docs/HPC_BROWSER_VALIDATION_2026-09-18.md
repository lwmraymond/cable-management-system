## 浏览器与 API 的实际分工

- **浏览器完成**：个人工作区、6 间房间、24 批 × 10 个机柜、样板柜的 7 台设备、6 条桥架，以及双层切换、单柜查看、端口搜索、自动路径预览和保存尝试。
- **正常 API 完成**：网页缺少入口的建筑、楼层、两种设备模板；其余 1,673 台设备通过 `/api/v1/scene/devices` 安装。保持应用限流，不直接写数据库、不绕过占位检查。批量部分耗时约 583 秒，支持按设备编号恢复并核对模板与 U 位。
- **只读数据库核对**：确认实际保存的 46,080 个端口，以及其他工作区的数据未被改动。
- 没有假称 1,680 台设备都逐台在浏览器操作，也没有把失败的线缆保存计为成功。

每间房间的四组机柜起始中心为 `(3,4)`、`(14,4)`、`(3,12)`、`(14,12)` m。每组 10 柜、5 列、2 行，间距 1.2 m、旋转 0°。主桥架折线点为 `(3,4,3.2) → (22,4,3.2) → (22,14.4,3.2)` m。此布局用于编辑器验证，未模拟冷热通道。

楼层总览按分区展开房间；当前产品会提示房间之间的展示距离不代表实测距离。两层均成功显示 120 柜、840 台设备，未混入另一个楼层。

## 已实测的可行项

- 通过网页创建 6 间房间、240 个机柜及 6 条桥架并持久化。
- 两类 NVIDIA 规划模板可安装，服务器及交换机端口随模板生成；机柜详情显示正确设备及 44/44U。
- 每个房间加载 280 台设备、7,680 个端口，没有数据截断。
- 单房间及整层可显示 3D；机柜定位可以放大查看正面设备。检查到的浏览器错误日志为空。
- 端口搜索可定位 DGX 与 Spectrum 的 OSFP 模型端口，自动路由能返回桥架标记、长度和预留。
- 与建模前备份对比，其他工作区的 locations、racks、devices、ports、device_templates、pathways、pathway_segments、cables 表行内容一致。

### 路由保存失败的证据

浏览器在第二层 C 机房选择：

- A：`HPC-F02-C-B01-01-DGX01 / OSFP-01`。
- B：`HPC-F02-C-B02-01-SN01 / OSFP-01`。
- 推荐段：`HPC-F02-C-TRAY-A`，登记 29.4 m。
- 预留 2 m 后，待保存登记长度 47.288 m。
- 点击「确认连接并保存」返回缺少项目错误。记录后关闭该草稿；数据库确认 0 条线缆。

未通过直接插入项目或线缆掩盖这项产品阻塞。未验证全量服务器互连、跨房间/楼层网络设计、物理光模块兼容性或真实链路状态。

## 硬件模板依据

DGX H200 的 8U 机身及接口布局依据 [NVIDIA DGX H100/H200 系统介绍](https://docs.nvidia.com/dgx/dgxh100-user-guide/introduction-to-dgxh100.html)。此模板按物理连接器建模：4 个 OSFP、4 个 QSFP112、2 个 QSFP28、2 个 RJ45；不把双端口适配器的逻辑通道误作额外物理插槽。

SN5600 的 2U、64 个 OSFP 加 SFP28 及管理连接依据 [NVIDIA SN5000 硬件介绍](https://networking-docs.nvidia.com/sn5000hw/introduction) 和 [硬件规格](https://networking-docs.nvidia.com/sn5000hw/specifications)。模板纳入 RJ45 管理端口，共 66 个网络模型端口；未把 USB、串口或电源接口计作网络端口。19 英寸面板宽度用于规划显示，不代表完整机箱 CAD 尺寸。
